# glossary

**annotation:** a wording or emphasis change made in one view only.

**claim:** a statement the user makes about the project in their own pitch. beholder checks claims against facts.

**fact:** one statement about the project with provenance and a confidence score.

**gap:** a criterion in the lens with no supporting fact.

**honesty guard:** the check that blocks export of any sentence resting on an unsupported fact.

**lens:** the structured definition of how one target judges: criteria, weights, trusted evidence, red flags, objections, vocabulary, formats.

**overclaim:** a claim that goes beyond what the facts support.

**pitch view:** the project model reframed through one lens, in nine fixed sections.

**preset:** a lens maintained by beholder from public criteria, with sources and a last-verified date.

**project model:** the single source of truth: all facts about the project with provenance.

**provenance:** where a fact comes from: file and lines, document and page, or user-stated.

**rubric:** an uploaded document (judging sheet, call for proposals, application guidelines) that becomes a lens.

**target:** the specific thing being pitched at, such as one hackathon track, one fund, or one partner type. the unit of the product.

**user-stated fact:** a fact the user typed in without document or code evidence. labeled as such and lower-trust by default.

**what not to lead with:** the section listing true facts that would hurt or distract with this reader.
